# 0.5.x bounded PHP body read A/B — 2026-09-16

This is an append-only working-tree measurement for the body-read deadline
slice. It is not a release claim. Both binaries were built for
`x86_64-pc-windows-msvc` and exercised by the same PowerShell 7 driver, local
PHP 8.5 NTS worker, one client connection, 20,000 measured requests and 2,000
warm-up requests per fresh server. Seven runs were collected per scenario and
the median is reported below. The candidate only adds a PHP body-read deadline;
empty PHP bodies take the existing no-read fast path.

Machine: Windows 11 Pro build 26200, Core i5-12400 (6 cores/12 logical), 32 GiB,
MSVC release build, Balanced power plan.

## In-memory HTTP control

The `/api` 404 control used 3 runs, 200,000 requests, concurrency 32 and 10,000
warm-up requests. Baseline medians were `120,838 RPS`, `0.241 ms`, `32.500
CPU us/request`; candidate medians were `116,940 RPS`, `0.249 ms`, `30.859
CPU us/request`. Run-to-run RPS ranges were 19.8% and 20.5%; this run is
therefore a variance check, not evidence of a body-path regression. The body
deadline is only passed to the PHP handler and does not run on this 404 path.

FACT: the empty-body PHP comparison does not show a reliable throughput loss;
the candidate is 1.3% below the baseline median while combined CPU is 8.0%
higher, but the seven-run CPU spread overlaps substantially. FACT: the body
carrying echo comparison is 1.1% above baseline RPS and 1.7% below combined
CPU. INFERENCE: the no-read fast path avoids a measurable timer cost on the
normal empty-body workload; this A/B is not large enough to distinguish small
PHP/process variance from a body-path cost. HYPOTHESIS: a larger body matrix
would be needed before optimizing allocation or frame-copy behavior.

  -Runs 7 -Requests 20000 -WarmupRequests 2000 -ScenarioFilter php_hello
pwsh -NoProfile -ExecutionPolicy Bypass -File .\benchmarks\php_worker.ps1 `
